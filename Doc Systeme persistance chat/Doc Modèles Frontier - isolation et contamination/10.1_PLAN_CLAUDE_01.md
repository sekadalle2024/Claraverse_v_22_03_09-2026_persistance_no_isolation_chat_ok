\## 3. Plan de solution (défense en profondeur)



Indépendamment de la confirmation exacte, la même règle métier ("ne jamais persister ni afficher une table dont le keyword contient Table\_Consolidation / Resultat / Table\_conso") doit être appliquée \*\*à chaque point d'entrée\*\*, pas seulement au premier trouvé. Centraliser la règle évite de la dupliquer et de l'oublier sur un futur chemin.



\### Solution 1 — Centraliser la règle d'exclusion



Créer une fonction unique, exportée, utilisée partout :



```typescript

// flowiseTableService.ts (ou un nouveau fichier tableExclusionRules.ts)

export const EXCLUDED\_TABLE\_KEYWORDS = \['table\_consolidation', 'resultat', 'table\_conso'];



export function isExcludedTableKeyword(keyword: string): boolean {

&#x20; const k = (keyword || '').toLowerCase();

&#x20; return EXCLUDED\_TABLE\_KEYWORDS.some(excluded => k.includes(excluded));

}

```



Avantage : un seul endroit à maintenir, et chaque appel devient un test unitaire trivial à écrire.



\### Solution 2 — Appliquer le filtre aux 3 chemins de sauvegarde/restauration connus



1\. \*\*`handleTableIntegrated()`\*\* (déjà fait, ligne 706-710) → remplacer par `isExcludedTableKeyword(keyword)`.

2\. \*\*`saveTablesBatch()`\*\* → ajouter le filtre dans la boucle `for (let i = 0; i < tables.length; i++)`, avant `tableRecords.push(...)`.

3\. \*\*`restoreTablesChronologically()`\*\* → filtrer `tableItems` avant la boucle d'injection :

&#x20;  ```typescript

&#x20;  const tableItems = timeline

&#x20;    .filter(item => item.type === 'table')

&#x20;    .filter(item => !isExcludedTableKeyword((item as TableTimelineItem).keyword)) as TableTimelineItem\[];

&#x20;  ```



\### Solution 3 — Filet de sécurité au niveau injection DOM (dernier rempart)



Ajouter la vérification directement dans `injectTableIntoDOM()` (fonction bas niveau, ligne 1377), de sorte qu'\*\*aucun\*\* chemin, même futur ou non identifié, ne puisse afficher une table exclue :



```typescript

private injectTableIntoDOM(tableData: FlowiseGeneratedTableRecord): void {

&#x20; if (isExcludedTableKeyword(tableData.keyword)) {

&#x20;   console.log(`🚫 \[DOM-GUARD] Injection bloquée pour keyword exclu: "${tableData.keyword}"`);

&#x20;   return;

&#x20; }

&#x20; // ... code existant

}

```



C'est le point le plus robuste : peu importe d'où vient l'appel (chemin connu ou inconnu), rien ne peut atteindre le DOM sans passer par cette fonction.



\### Solution 4 — Corriger la contamination inter-sessions (H1, sous réserve de confirmation)



Une fois `flowiseTimelineService.ts` obtenu, vérifier que `getSessionTimeline(sessionId, messages)` filtre bien ses résultats sur `sessionId` avant de les retourner. Ajouter un filtre défensif supplémentaire côté appelant si nécessaire :



```typescript

const timeline = (await flowiseTimelineService.getSessionTimeline(this.currentSessionId, messages))

&#x20; .filter(item => item.sessionId === this.currentSessionId);

```
