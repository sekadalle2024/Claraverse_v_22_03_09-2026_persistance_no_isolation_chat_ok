RÉSOLUTION DÉFINITIVE : Code Désactivation Absent du Bundle

📋 DIAGNOSTIC COMPLET

Root Cause Identifiée

Problème : Le code de blocage des tables Table\_Consolidation, Resultat, Table\_conso présent dans flowiseTableBridge.ts (lignes 706‑710) n’est pas inclus dans le bundle de production (dist/assets/index-\*.js).



Causes probables :



Cache Vite corrompu – node\_modules/.vite conserve d’anciennes versions transformées, même après rm -rf dist node\_modules/.vite.



Tree‑shaking agressif – Le bundler esbuild considère que le bloc est « mort » car :



EXCLUDED\_KEYWORDS est une variable locale jamais réutilisée.



Les console.log peuvent être supprimés en mode production.



Le return anticipé est identifié comme du code sans effet secondaire observable.



Appel par un autre chemin – La sauvegarde pourrait passer par saveTablesBatch qui ne contient pas le blocage.



Preuves :



powershell

\# Build sans minification pour inspecter

npm run build -- --minify false

grep "EXCLUDED\_KEYWORDS" dist/assets/index-\*.js

\# Résultat : AUCUNE occurrence ❌

→ Le code est absent même sans minification, ce qui écarte l’hypothèse de suppression des console.log.



✅ SOLUTION RETENUE – DÉFENSE EN PROFONDEUR (3 NIVEAUX)

Principe

Placer le blocage à trois niveaux indépendants pour garantir que les tables exclues ne soient jamais sauvegardées ni restaurées, quel que soit le chemin d’exécution et l’état du cache Vite.



Niveau Service (flowiseTableService.saveGeneratedTable) – blocage au cœur de la persistance (survit à tout tree‑shaking).



Niveau DOM (index.html en capture) – blocage avant même que l’événement n’atteigne le bridge.



Niveau Restauration (flowiseTableBridge.restoreTablesForSession) – filtrage des tables exclues lors de la reconstruction.
